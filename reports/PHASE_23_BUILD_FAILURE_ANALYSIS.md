## 2. Phase 22 Build & Packaging Triage (The 9 Core Questions)

### Question 1: What artifact was actually produced in Phase 22?
Phase 22 executed `scripts/build_distribution_bundle.ps1` and produced:
1. An unpacked directory bundle: `dist/ZITERA_LAB_WINDOWS_X64/` (53 items, ~36.8 MB uncompressed).
2. A compressed ZIP archive: `dist/ZITERA_LAB_WINDOWS_X64.zip` (24,900,381 bytes, ~24.9 MB).

### Question 2: Was that artifact a portable application bundle or a Windows installer?
The artifact was strictly a **portable application folder and ZIP archive**. It contained `zitera_lab.exe`, `flutter_windows.dll`, CRT runtime DLLs, `engine/zitera-engine.exe`, and data files. It was **NOT** an installer.

### Question 3: Was there actually a dedicated `Setup.exe` created?
**NO.** There was no dedicated Windows Setup executable (`Setup.exe`, `ZiteraLab-Setup.exe`, or `.msi`) generated by Phase 22. 

### Question 4: Which file was expected by the user to run or install the application?
- If the user expected an **installation experience** ("memasang aplikasi"), they naturally looked for a `Setup.exe`, `installer.exe`, or wizard.
- If the user attempted to run the portable app, they were expected to open `dist/ZITERA_LAB_WINDOWS_X64/` and run `zitera_lab.exe`.
- However, if the user received `ZITERA_LAB_WINDOWS_X64.zip` and double-clicked `zitera_lab.exe` **inside Windows Explorer without extracting the ZIP first**, Windows executed `zitera_lab.exe` inside an isolated temporary directory (`%TEMP%\Temp1_...`) without extracting the dependent `engine/` directory, `data/` folder, or CRT DLLs, causing an instant startup failure.

### Question 5: What was the last recorded build and packaging command?
The final bundle build command in Phase 22 was:
```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File scripts\build_distribution_bundle.ps1 -SkipBuild
```

### Question 6: Was the exit code available?
Yes. The command completed synchronously with exit code `0`.

### Question 7: Were there error outputs, missing dependencies, invalid paths, resource mismatches, or packaging failures?
- In the automated CI / local development testing environment, `build_distribution_bundle.ps1` and `test_bundle_integration.ps1` reported `14/14 PASS` with exit code 0.
- However, inspecting the legacy installer script `scripts/installer/install_user.ps1` reveals a severe packaging mismatch: line 80 explicitly looks for `dist\bin\zitera-engine.exe` (Phase 20 CLI path), which is completely absent from the Phase 22 Flutter bundle layout (`dist\ZITERA_LAB_WINDOWS_X64\engine\zitera-engine.exe` and `zitera_lab.exe`). Anyone attempting to run `install_user.ps1` would immediately fail with `FileNotFoundException`.
- Furthermore, the Inno Setup script `installer/windows/zitera_setup.iss` was last updated in Phase 20 and only referenced `dist\bin\zitera-engine.exe`, having never been updated to package the Flutter desktop application (`zitera_lab.exe`, `flutter_windows.dll`, and `data/`).

### Question 8: Can the runtime failure be confirmed from existing evidence?
- **CONFIRMED:** The repository lacked an updated Windows installer for the Flutter desktop application.
- **CONFIRMED:** Legacy installer scripts (`install_user.ps1`, `zitera_setup.iss`) point to non-existent Phase 20 paths (`dist/bin/zitera-engine.exe`).
- **CONFIRMED:** The binaries are not signed with a trusted commercial Authenticode certificate (only internal Ed25519 signature for the engine catalog). On standard consumer Windows machines, launching unsigned executables triggers Windows SmartScreen warnings ("Windows protected your PC").

### Question 9: What causes remain unknown / lack evidence?
The exact user-facing error dialog, OS exception code, or screenshot encountered by the owner on their test machine was not provided in the prompt. We cannot state with 100% certainty whether the owner experienced:
a) Confusion from the absence of a `Setup.exe` installer wizard,
b) Windows SmartScreen or antivirus heuristic quarantine, or
c) An unextracted ZIP execution failure.
